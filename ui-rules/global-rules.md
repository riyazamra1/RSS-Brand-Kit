# RSS Global UI Rules

1. Modern, premium, professional, lightweight Android UI.
2. Preserve the original RSS company logo unchanged: no recoloring, stretching, distortion, redesign, replacement, or oversized placement.
3. Every RSS app uses its own original project/app logo for app identity. The RSS company logo is reserved for designated company-branding areas.
4. Use consistent spacing, typography, corner radius, elevation, and touch targets.
5. Cards generally use a meaningful icon on the left and content on the right where appropriate.
6. Use meaningful colorful icons throughout app content where appropriate.
7. Avoid obsolete-looking UI.
8. **Animation is the default everywhere**: registration, welcome, feature pages, main app, navigation, settings, about, contact, privacy, terms, loading, and meaningful interactions.
9. Animations must be smooth, purposeful, lightweight, and accessibility-aware; avoid gratuitous motion.
10. Light, dark, and system appearance must update the complete application consistently.
11. Responsive layouts must work across Android screen sizes and orientations.
12. Use clear hierarchy, readable contrast, and accessible touch targets.
13. Slide navigation uses the RSS glassmorphism standard defined in \`slide-menu.md\`.
14. Common RSS pages and components should reuse RSS KIT behavior rather than reimplementing divergent visual patterns.

Priority: project-specific explicit instructions override these rules for that project.
